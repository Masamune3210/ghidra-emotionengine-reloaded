# DECKARD APU Ghidra language v1 (2026-10-15)

## Purpose / decisions

A separate `PowerPC:BE:32:DECKARD` language variant built on the *existing* Ghidra PowerPC 4xx SLEIGH language. Its source is only an extra `.sinc` file, a small wrapper `.slaspec`, and an independent `.ldefs`. Generic `PowerPC:BE:32:default`, `PowerPC:BE:32:4xx`, and PS2 EE/IOP definitions are not modified.

This addresses **DECKARD's custom PowerPC APU opcodes**, not BIOS module detection or IOP IRX imports. All firmware byte sequences remain unchanged.

## Install / verify on Windows (Ghidra 12.1.x)

Run from PowerShell. Replace `C:\path\to\ghidra_12.1.3_PUBLIC` with the actual installed directory.

```powershell
py .\install_deckard_language_20261015_v1.py "C:\path\to\ghidra_12.1.3_PUBLIC"
py .\install_deckard_language_20261015_v1.py "C:\path\to\ghidra_12.1.3_PUBLIC" --install
```

The first command is strictly read-only. The second command adds only `deckard.ldefs`, `ppc_32_deckard_be.slaspec`, `deckard_apu.sinc`, and its compiled `ppc_32_deckard_be.sla` under `Ghidra/Processors/PowerPC/data/languages/`. Nothing is overwritten. If compilation fails, the newly installed names are removed. The compiler comes from the **same installed Ghidra version** so the output `.sla` format matches. The Ghidra installation must be writable. Restart Ghidra after installation.

If the install cannot locate Sleigh, pass `--sleigh "C:\path\to\ghidra_12.1.3_PUBLIC\support\sleigh.bat"` as appropriate.

Back up the Ghidra project, and **import the DECKARD ELF afresh** with language `PowerPC:BE:32:DECKARD` for validation before trying to migrate the existing database. DPATCH should be imported raw at `0xFFFFD000`; LOADER should be imported separately and re-based at `0xFFFFE000` (reset at `0xFFFFFFFC`). The original PowerPC databases remain untouched. Run auto analysis on the new imports, then run `AuditDeckardApuDecode_20261015_v1.java` for exact verified instruction checks.

## Coverage and semantics

- 32 named opcode constructors, sourced from El_Isra's PowerPC Monitor documentation.
- 291 nonzero primary-opcode-zero **candidate words** in existing DECKARD ELF and DPATCH evidence; 246 match documented instructions with valid unused register-field bits, and 45 remain deliberately unmatched. Many unmatched words are inline data, or do not follow the documented APU encoding.
- `amtpc`, `amfpc`, cycle count, HI, LO, indexed GPR, indexed GTE, and decode register operations retain read/write register direction in p-code.
- Hardware side effects are emitted as **opaque SLEIGH userops**, not modeled as absent or mistaken for ordinary PowerPC instructions. `aexec/aexeci/aexecn` also expose the instruction-class result through `cr6`. This makes static decompilation more informative, but does not claim to emulate Sony's APU hardware or track its complete state.
- No blanket `OP=0` catchall, no invented behavior for `0x30C` (`aunk0` remains opaque), and no rewriting invalid words into NOPs.
